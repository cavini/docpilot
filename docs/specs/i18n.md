# Spec: Internationalisation

Status: accepted Milestone: M3

## Problem and goal

The app is bilingual from M0 — English and Brazilian Portuguese, with a locale
switcher and routing already in place. What M3 adds is a lot of new interface,
and the risk is that half of it ships with English hard-coded into the
components.

The goal is that every user-visible string, date, number and file size comes
from a message catalogue, and that a missing translation fails loudly in
development rather than silently showing a key.

## Behaviour

**Two catalogues**, `messages/en.json` and `messages/pt-BR.json`, with the same
keys. English is the source; `pt-BR` is a real translation, not a copy.

**No literal user-visible strings in components.** Including the ones that feel
too small to translate: button labels, empty states, error messages,
`aria-label`s, and the text a screen reader reads.

**Formatting is localised, not concatenated.** A date is formatted for the
locale, not assembled from parts. A file size is `1,2 MB` in pt-BR and `1.2 MB`
in English. A count that can be one or many uses a plural rule rather than
`${n} document(s)`.

**Server messages are not translated.** An API error's `message` is English and
is shown as received. Translating it would mean either a catalogue of every
server message in the client — which goes stale the moment the server reworded
one — or sending a locale to the API, which is a decision for when there is a
second consumer. What _is_ localised is the surrounding interface: the retry
button, the heading, the explanation. The stable `code` is what the client
branches on, and where a code deserves a friendly sentence, that sentence lives
in the catalogue keyed by the code.

**The answer's language follows the question,** not the interface. Someone
reading the app in Portuguese can ask in English and should get English back.
That instruction is already in the system prompt.

## Acceptance criteria

**AC1.** Given the English and pt-BR catalogues, when they are compared, then
they have exactly the same set of keys.

**AC2.** Given a component, when it is rendered, then no user-visible string is
a literal in the source.

**AC3.** Given a missing key, when it is requested in development, then it
throws rather than rendering the key.

**AC4.** Given a date, when it renders, then it is formatted for the active
locale.

**AC5.** Given a file size, when it renders, then its decimal separator and unit
follow the locale.

**AC6.** Given a count, when it renders, then it uses the locale's plural rule.

**AC7.** Given `/pt-BR`, when any M3 page loads, then every string on it is
Portuguese.

**AC8.** Given the locale switcher, when the locale changes, then the current
page re-renders in the new locale and the path updates.

**AC9.** Given a server error with a known `code`, when it is shown, then the
explanation around it is localised while the server's own message is shown as
received.

## Edge cases and failure modes

| Situation                    | Behaviour                                                |
| ---------------------------- | -------------------------------------------------------- |
| A key exists in English only | The key-parity test fails in CI                          |
| An untranslated string ships | Caught by the lint rule, and by the pt-BR e2e assertions |
| A locale not in the list     | Routing falls back to the default                        |

## Non-goals

- A third language. The architecture takes one; adding one is not in scope.
- Right-to-left layout.
- Translating the documents themselves, or the model's answers.
- Translating API error messages.

## Test plan

| AC       | Level           | File                                  |
| -------- | --------------- | ------------------------------------- |
| AC1      | unit            | `apps/web/src/i18n/messages.test.ts`  |
| AC4–AC6  | unit            | `apps/web/src/i18n/format.test.ts`    |
| AC3, AC9 | component (RTL) | `apps/web/src/features/**/*.test.tsx` |
| AC2      | lint            | ESLint rule over `apps/web/src`       |
| AC7, AC8 | browser e2e     | `apps/web/e2e/i18n.spec.ts`           |

AC1 is a test rather than a convention because key drift is invisible until a
user sees a raw key, and it happens on every change to the interface.
